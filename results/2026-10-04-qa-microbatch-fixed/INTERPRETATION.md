# 固定 64 token：排除回答长短后的合批收益

288 次测量全部成功，每条都生成 **64 token**，合计 **18,432 token**。4 个闭环 HTTP 客户端下，batch4 的短/长资料吞吐量分别为原服务的 **3.50× / 3.45×**。三轮均有收益，支持合批的提升不只是来自自然回答变短。

这是一项固定工作量控制。它禁止提前 EOS，会强制模型在答案已完成后继续生成，**不能用来评价回答质量，也不能把 3.5× 当作日常问答加速承诺**。实际自然回答的吞吐收益为 **1.41× / 2.21×**，见 [864 条自然回答报告](../2026-10-04-qa-microbatch/INTERPRETATION.md)。

## 4 个客户端的完整 HTTP 数据

每个条件 3 轮 × 12 次请求。延迟合并 36 次请求取中位数/P95；吞吐量为总完成数除以三轮完整负载组耗时，包含排队、凑批、检索、分词、生成和流式传输，不含模型加载、预热和浏览器绘制。

|---|---|---:|---:|---:|---:|---:|
| 短 | 原串行服务 | 6.350 | 8.553 | 12.730 | 0.407 | 26.02 |
| 短 | batch1 控制 | 7.278 | 9.756 | 11.080 | 0.410 | 26.21 |
| 短 | batch2 | 2.351 | 4.454 | 5.221 | 0.861 | 55.09 |
| 短 | batch4 | 0.171 | 2.286 | 4.865 | 1.424 | 91.15 |
| 长 | 原串行服务 | 7.275 | 9.488 | 11.612 | 0.402 | 25.75 |
| 长 | batch1 控制 | 7.400 | 10.148 | 11.528 | 0.390 | 24.99 |
| 长 | batch2 | 2.656 | 4.879 | 5.567 | 0.803 | 51.38 |

## 为什么比自然回答的收益大？

自然回答长短不同，静态批次需要生成到最长的一行结束，短行之后的填充不计入有效输出，`done` 也等待整批完成。固定 64 token 时每行等长，消除了这类 EOS 后的批内等待。同时，实际批次成员还受 HTTP 到达和目标 10 ms 凑批窗口影响，batch4 不保证每次恰好 4 条。

因此两组回答了不同问题：自然回答体现当前演示的实际体验；固定长度展示相同输出工作量下的批量执行收益。这里只测这一模型、机器和输入范围，没有把加速归因到某一个 Attention/Linear 内核，也没有测持续开放到达的生产容量。

## 完整性与输出检查

- 4 种方法 × 2 种资料长度 × 3 轮 × 12 次请求，共 **288 条**。另有 **144 条预热**不计入数据。四种方法均使用相同的 GPU eager BF16、固定权重 revision 和本地缓存。
- 所有成功请求的同题、同资料非填充输入哈希一致，输出均为 64 token。最大 PyTorch 分配显存约 3599 MiB（3.52 GiB），属于 allocator 峰值。
- batch1 的 **72/72** 输出 token 与原服务完全相同；batch2 的 **42/72**、batch4 的 **47/72** 发生变化。这是数值/生成路径差异记录，不是正确率统计。
- 测量时的早期脚本在原始行中仍保存了关键词字段；本组的这些字段**没有质量意义，不用于结论**。当前汇总明确输出 `keyword_passes: null`，新版测量器也不再给固定长度控制打分。保留测量源码和原始行，避免事后改写证据。
- 原自然回答中的企业版价格幻觉未解决。固定长度结果不构成部署验收。

## 复现

```powershell
$env:HF_HUB_OFFLINE='1'
$env:TRANSFORMERS_OFFLINE='1'
python qa_batch_benchmark.py --output results/my-microbatch-fixed --trials 3 --clients 4 --fixed-tokens --max-new-tokens 64
python qa_batch_benchmark.py --output results/2026-10-04-qa-microbatch-fixed --verify-only
python analyze_qa_batch.py --run results/2026-10-04-qa-microbatch-fixed
```

[metadata.json](metadata.json) 保存环境、参数和测量源码哈希；[requests.jsonl](requests.jsonl) 保存原始请求与 token；[comparison.csv](comparison.csv) 和 [analysis.json](analysis.json) 为可重算汇总。分析文件记录按 LF 规范化的输入哈希和分析源码归档位置，源码归档本身保留原始字节。完整实验环境和有限闭环负载的限制与自然回答报告相同。
